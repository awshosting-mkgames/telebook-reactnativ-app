TeleBook Socket Contract

Every socket event the backend sends and accepts, what each one expects, and the exact client code for connecting, messaging, read ticks and push notifications. Following the five rules below is what makes online status and read ticks behave correctly.

The five rules

  1. Connect with the JWT in the handshake — io(URL, { auth: { token } }). The server identifies the user from the token, puts the socket in that user's room and marks them online. No setup event is needed.
  2. Send messages over REST only — POST /api/messages. Never emit new-message. The server delivers to every recipient and sends push notifications itself. The socket new-message event is now ignored.
  3. On every message-received, emit message-delivered; if that chat is open on screen, also emit message-read. This is what turns the sender's single tick into double grey and then double blue.
  4. Disconnect the socket when the app goes to background, reconnect when it becomes active. Push notifications are sent only when a user has no live socket. A socket left open in background means the user looks online and receives no notifications.
  5. Emit join-chat when a chat screen opens and leave-chat when it closes — and re-join after every reconnect. Typing indicators, deletions, edits and reactions are sent only to sockets inside the chat room.

What changed on the backend

Two reported issues were caused on the server and are fixed there. Nothing in the app needs to change for the fixes to take effect, but the rules above are what let them work fully.

IssueCauseNow
Push notifications arrived while the user was online Online status expired after 30 s unless the app sent heartbeat every 25 s. A reconnect or a second device could also wipe it. The server tracks every open socket itself. A user is online while any socket is connected. heartbeat is no longer needed.
Sender stayed on a single tick after the receiver read the message from another screen Opening a chat loads messages over REST, which saved the read but never told the sender. GET /api/messages/:chatId and PUT /api/messages/:id/read now emit message-read-update to the sender, the same event the socket path sends.

Connecting

One socket for the whole app, created after login. This service handles authentication, reconnects, the background rule and re-joining the open chat.

// services/socket.js
import { io } from 'socket.io-client';
import { AppState } from 'react-native';

const SOCKET_URL = 'https://api.telebookservices.com';

let socket = null;
let appStateSub = null;
let openChatId = null;           // the chat currently on screen

export function connectSocket(token) {
  if (socket) return socket;

  socket = io(SOCKET_URL, {
    transports: ['websocket'],
    auth: { token },                   // rule 1 — server reads the user from this
    reconnection: true,
    reconnectionDelay: 1000,
    reconnectionDelayMax: 10000,
  });

  socket.on('connect', () => {
    // Rooms are per socket. After any reconnect the chat room is gone —
    // join it again (rule 5). The personal room is rejoined by the server.
    if (openChatId) socket.emit('join-chat', openChatId);
  });

  socket.on('connected', () => { /* server has marked this user online */ });
  socket.on('connect_error', (err) => console.warn('socket:', err.message));

  // Rule 4 — background means offline, so push notifications reach the user
  appStateSub = AppState.addEventListener('change', (state) => {
    if (state === 'active') {
      if (!socket.connected) socket.connect();
    } else if (state === 'background') {
      socket.disconnect();             // not on 'inactive' — iOS enters that briefly
    }
  });

  return socket;
}

export function disconnectSocket() {     // call on logout
  appStateSub?.remove();
  socket?.disconnect();
  socket = null;
  openChatId = null;
}

export const getSocket = () => socket;
export const setOpenChat = (chatId) => { openChatId = chatId; };
export const getOpenChat = () => openChatId;

Why disconnect instead of staying connected in background: the backend sends a push only to users with no live socket. Disconnecting is also what sets last seen correctly.

Message lifecycle

The full path of one message from A to B, and which side does what.

1
A calls POST /api/messages with { chatId, content, messageType }. The response is the saved message — show it with a single tick.
2
Server emits message-received to every other member. Members with no live socket also get a push notification.
3
B receives message-received and emits message-delivered — even if B is on another screen.
4
Server emits message-delivered-update to A. A shows double grey.
5a
B, if that chat is already open: emits message-read.
5b
B, if B opens the chat later: calls GET /api/messages/:chatId. The server marks every unread message as read — nothing to emit.
6
Server emits message-read-update to A for each message, in both 5a and 5b. A shows double blue.

Sending

const { data } = await api.post('/api/messages', {
  chatId, content, messageType: 'text',   // 'text' | 'image' | 'video' | 'audio' | 'document' | 'emoji'
  replyTo,                                 // optional message _id
  attachments,                             // optional — upload first via POST /api/users/media
});
addToChat(data.message);                   // single tick
// Do NOT emit 'new-message'. The server has already delivered it.

Receiving

import { getSocket, getOpenChat } from './socket';
import { AppState } from 'react-native';

socket.on('message-received', (message) => {
  const chatId = message.chat?._id ?? message.chat;

  socket.emit('message-delivered', { messageId: message._id });          // always — rule 3

  const onScreen = chatId === getOpenChat() && AppState.currentState === 'active';
  if (onScreen) {
    socket.emit('message-read', { messageId: message._id, chatId });      // only when actually visible
  }

  upsertMessage(message);                  // chat screen, chat-list preview, unread badge
});

Opening and closing a chat

export async function openChat(chatId) {
  setOpenChat(chatId);
  getSocket()?.emit('join-chat', chatId);                     // rule 5
  const { data } = await api.get(`/api/messages/${chatId}`);
  // This call marks all unread messages as read and notifies their senders.
  // It also resets this chat's unseenCount to 0 on the server.
  return data;
}

export function closeChat(chatId) {
  getSocket()?.emit('leave-chat', chatId);
  setOpenChat(null);
}

Showing ticks

For messages you sent. Update the message's deliveredTo / readBy arrays when the update events arrive, then derive the tick from them:

✓
Sent
saved; no recipient in deliveredTo
✓✓
Delivered
every recipient in deliveredTo
✓✓
Read
every recipient in readBy
socket.on('message-delivered-update', ({ messageId, userId, chatId }) =>
  addReceipt(messageId, 'deliveredTo', userId));

socket.on('message-read-update', ({ messageId, userId, chatId }) => {
  addReceipt(messageId, 'readBy', userId);
  addReceipt(messageId, 'deliveredTo', userId);   // read implies delivered
});

export function tickState(message, myId, chatUsers) {
  const others = chatUsers.map((u) => String(u._id)).filter((id) => id !== String(myId));
  const has = (list, id) => (list || []).some((r) => String(r.user) === id);
  if (others.every((id) => has(message.readBy, id)))      return 'read';
  if (others.every((id) => has(message.deliveredTo, id))) return 'delivered';
  return 'sent';
}

In groups, every means blue ticks appear once all members have read. Use some if the product wants blue on first read.

Presence and typing

socket.on('user-online',  (userId) => setPresence(userId, 'online'));
socket.on('user-offline', (userId) => setPresence(userId, 'offline', new Date()));

// When a chat opens, ask once — don't wait for a broadcast
socket.emit('get-user-status', { userId: otherUserId });
socket.on('user-status-result', ({ userId, status }) => setPresence(userId, status));

// Typing — debounce so it isn't sent on every keystroke
let typingTimer;
function onChangeText(text) {
  if (!typingTimer) socket.emit('typing', { chatId });
  clearTimeout(typingTimer);
  typingTimer = setTimeout(() => { socket.emit('stop-typing', { chatId }); typingTimer = null; }, 2000);
}
socket.on('typing',      ({ chatId, userId }) => showTyping(chatId, userId, true));
socket.on('stop-typing', ({ chatId, userId }) => showTyping(chatId, userId, false));

A user counts as online while any of their devices has a live socket. Closing one of two phones does not mark them offline.

Push notifications

The server sends a push only when the recipient has no live socket — the app is in background (rule 4), closed, or offline. While the app is open, messages arrive as message-received instead.

Register the device token

// At login
await api.post('/api/auth/verify-otp', {

Force-closed app: if the OS kills the app without closing the socket, the server needs up to about 85 seconds to notice. Messages in that window arrive without a push. Normal backgrounding does not have this gap because rule 4 closes the socket immediately.

Common mistakes

Emitting new-message after sending. The server ignores it — by the time the REST call returns, every recipient has already been sent the message. Leaving it in only adds traffic.

Not re-joining the chat room after a reconnect. Typing, deletes and reactions stop arriving silently. The connect handler in the service above takes care of it.

Emitting message-read for a chat that isn't visible. The sender sees blue ticks for a message nobody read. Check the open chat and AppState.currentState === 'active'.

Keeping the socket connected in background. The user looks online and gets no push notifications.

Reading data.isGroup as a boolean. FCM data values are strings; "false" is truthy.

Test before release

Two phones, users A and B. Each item should pass.

  • A and B both open, B on the chat list. A sends a message. B gets no push notification. B's chat list updates. A sees double grey.
  • B then opens the chat. A's ticks turn blue within about a second.
  • Both on the same chat screen, chatting. Blue ticks immediately; typing indicator shows on both sides.
  • B sends the app to background. A sends a message. B gets a push. Tapping it opens that chat.
  • B turns on airplane mode for 20 seconds, then off. B reconnects on its own; typing and reactions still work in the open chat.
  • B signed in on two phones; close the app on one. A still sees B as online.
